# story-hand-curl-tuning-basic — curl 正規化と Visual キャリブレーション基礎

この story は、ESP 側でキャリブレーション済みの LucidGloves ポテンショメータ値を Unity に直接取り込み、  
指ごとの curl 値（0〜1）に正規化したうえで、  
VR 上の手の見た目と実際の手の動きが大きく破綻しないことを確認するための **最小セット** を定義する。

---

## 受け入れ条件（完了判定）

### 1. シリアル入力のマッピング / フラグ

- Unity 実行中、シリアルで受信した文字列（例: `A2301B2391C3431D3313E1234`）が  
  以下の対応でパースされていることが確認できる:

  - A → 親指 (thumb)
  - B → 人差し指 (index)
  - C → 中指 (middle)
  - D → 薬指 (ring)
  - E → 小指 (pinky)
  - K → キャリブレーション中フラグ（行末または行内に付与される）

- デバッグ UI やログなどで、各フレームの生値 `sensorRaw[0..4]` が確認できる。
- `K` を含む行を受信しているかどうかを Unity 側で判定できる（例: `HandSensorReceiver.isCalibrating`）。

### 2. curl 正規化の挙動

- ESP 側のキャリブレーションにより、以下が成り立つこと:

  - 指を伸ばした（ホームポジション）状態で  
    各指の `sensorRaw[i]` が 0 に近い値になる。
  - 完全に握った状態で  
    各指の `sensorRaw[i]` が 4095 に近い値になる。

- Unity 側で `curl01` を 0〜1 に正規化した結果として、以下が成り立つこと:

  - ホームポジションの状態で `curl01[i]` が 0 に近い値（例: 0.0〜0.1）になる。
  - 完全に握った状態で `curl01[i]` が 1 に近い値（例: 0.9〜1.0）になる。

### 3. 見た目と実際の手の一致

- ESP 側キャリブレーションと BaseHand プレハブの調整が済んだ状態で、  
  以下の感覚的な整合性が取れていること:

  - ホームポジションで、VR 上の手の形と実際の手の形が大きく乖離していない。  
    （指が明らかに曲がりすぎている / 反っている などがない）
  - 指をゆっくり曲げ伸ばししたとき、`curl01` の変化と VR 上の指の動きが  
    概ね同期して見える（遅延やガクつきが目立たない）。

### 4. K フラグとキャリブレーション中の挙動

- ESP 側でセンサキャリブレーションを行う際、`K` フラグ付きのシリアル文字列を送信する。

  - 例: `A123B456C789D012E345K`（A～E の 5 チャンネル + 任意位置の K）

- Unity 側では、以下の挙動が確認できること:

  1. `K` フラグ受信中:

     - 受信コンポーネント（HandSensorReceiver）が受信行内の `K` を検知するとき、
       - `isCalibrating = true` になる。
       - その間は `HandCurlTracker.UpdateSensorFromEncodedString(...)` を呼ばず、
         `sensorRaw` / `curl01` は前フレームの値を保持する（指の動きが凍結する）。
     - `HandFreezeOnCalibrate` などのコンポーネントが
       `HandSensorReceiver.isCalibrating` を監視し、
       - 立ち上がり時に手の位置・向きを保存
       - `isCalibrating == true` の間は手の Transform を保存値に固定  
       → VR 上の手が空間的にも完全に止まって見える。

  2. `K` フラグが来なくなった時点:

     - `isCalibrating = false` に戻る。
     - `HandCurlTracker` へのセンサ更新と、手の追従が再開する。
     - 以降、ESP 側でキャリブされた 0〜4095 の値が  
       `curl01`（0〜1）→ `HandVisualFromCurl` → VR 手モデルへと反映される。

- 本 story では、**視覚側の追加キャリブレーション UI（ボタン）** は持たず、
  - センサ値のキャリブレーションは ESP 側、
  - Visual のホームポジションは BaseHand プレハブのポーズ  
  で決める構成であることを明示する。

### 5. デバッグ確認手段

- 少なくとも以下のどれかで、開発者が状態を確認できる:

  - インスペクタ / デバッグ UI 上で  
    `sensorRaw[i]` / `curl01[i]` / フィルタ後の curl などの値を表示する。
  - 必要に応じてログ出力を ON/OFF できる。

- 「センサ値 → curl → 指の角度」の流れが追えるようになっていること。
