# ピアノ連動（鍵盤 ↔ 触覚フィードバック）

## 背景
- 本プロジェクトは XR 上でピアノ演奏を行い、触覚（Force Feedback）を返すことを目的とする。
- 触覚の生成は「サーボ制御（シリアル送信）」と「ピアノ側のイベント（接触/底面/押下）」の連動で成立する。

## スコープ
- ピアノ鍵盤スクリプトから、触覚送信側へ渡すべき情報（押下/底面/モード等）の整理
- 物理押下（手コライダー）と MIDI 再生（自動アニメーション）を区別して扱う方針
- 将来の「ピアノ触覚モード」遷移の設計メモ

## 非スコープ
- 触覚のシリアル送信仕様やキャリブレーション方式（別 feature で扱う）
- ESP32 ファームウェア変更

## 既存コード参照（現状把握）
- 物理押下・底面判定：
  - `Assets/Scripts/Piano/PianoKey.cs` の角度ベース判定（`transform.eulerAngles.x`）を利用
  - `PianoKeyController.PressAngleThreshold`（既定 355°）より下がると底面に近づくため、指ごとの送信停止トリガーに利用できる
- MIDI 再生時の鍵盤アニメーション：
  - `PianoKey.Play()` 経由で鍵盤が動くが、触覚は「物理押下（手コライダー起因）」にのみ反応させる方針
- 再生モード（KeyMode）：
  - `KeyMode` は鍵盤アニメーション等のために存在する
  - **現状の触覚送信は `KeyMode` と連動しない**（必要になったら別ストーリーで扱う）

## 実装メモ（接触検出）
- 鍵盤（`PianoKey.001`〜`PianoKey.088`）側で Collision を受け、相手の `FingerColliderId` から「どの手・どの指か」を取得する。
  - 指先のみ判定: `FingerColliderId.segmentIndex==0` を採用する。
- 底面判定は鍵盤角度（`transform.eulerAngles.x`）で行い、`x <= 352.5f` を底面到達として扱う（`0°` 表示になる場合は `+360` 補正して判定する）。

## 将来拡張（別ストーリーで扱う）
- ピアノ鍵盤接触での「ピアノ触覚モード」遷移、底面到達で指ごと送信停止
- 通常時の「先行係数（曲げ量よりわずかに先行）」の導入（パラメータ化）
- 指ごとのオフセット保存、キャリブレーション値の永続化（PlayerPrefs 等）

## 関連（要件の所在）
- ランタイムの触覚生成（通常/ピアノ触覚モード、底面停止）は `feature/haptics-runtime-feedback.md` / `story/haptics-runtime-feedback-piano-mode.md` にまとめる。
